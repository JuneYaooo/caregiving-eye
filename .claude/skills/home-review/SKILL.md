# 家庭记录回顾

米执事**不录全天视频**。它留下的是：每条提醒的文字、出事时的快照和前后约 25 秒的短录像、进出通报和快照、全天活动统计（没有画面），以及一张空房间底图。完整录像如果有，在摄像头自己的 SD 卡或米家云存储里，不在这台电脑上。

所以回答问题的思路是**由粗到细、能不看图就不看图**：先读几 KB 的文字记录定位，再只看相关的几张图，最后才动录像。先读文字只要几秒；一上来就翻图片，几十张图会把上下文和时间都耗光。

## 数据在哪

先找事件目录：仓库根目录的 `events/`，或 `.env` 里 `EVENTS_DIR` 指定的位置。米执事通常跑在另一台 Windows 机器上，本机找不到就问用户要路径，不要猜。

| 文件 | 内容 | 什么时候看 |
|---|---|---|
| `alerts.jsonl` | 每条通报：`ts` `level` `type` `text` `snapshot` `clip` | 一切问题的起点（用下面的脚本读） |
| `incidents.jsonl` | 结案事件：持续时长、`acked`（false=主人说误报，true=属实，ok=收到，me=是我） | 判断一条提醒是真是假 |
| `snap_<类型>_<YYYYMMDD_HHMMSS>.jpg` | 事件或进出时刻的原图 | 需要核实时 |
| `clips/clip_<类型>_<时间>.mp4` | 事件前 10 秒到后 15 秒，640 宽 | 快照看不清经过时 |
| `base_<YYYYMMDD>.jpg` | 当天空房间底图 | 比较“东西有没有变” |
| `activity_person_<日期>.json` / `activity_pet_...` | 每小时活跃度、区域停留、最早最晚出现 | 作息、活动量问题 |
| `status.json` | 当前模式、警觉等级、画面是否在线、各档位时间占比 | “现在怎样”“系统正常吗” |

## 两个脚本

```bash
# 一页时间线：同一件事的催办会合并成一行，并标出确认结果（主人确认误报 / 属实 / 未确认）
python .claude/skills/home-review/scripts/day_digest.py --events-dir events [--day 20261101] [--from 13:00 --to 18:00] [--json]

# 画面变化：比纹理不比亮度，扛光照变化
python .claude/skills/home-review/scripts/scene_diff.py compare A.jpg B.jpg [--roi x1,y1,x2,y2] [--out diff.jpg]
python .claude/skills/home-review/scripts/scene_diff.py scan   --video rec.mp4 | --images 'events/snap_*.jpg' [--step 600] [--roi ...]
python .claude/skills/home-review/scripts/scene_diff.py bisect --video rec.mp4 --start S --end S [--roi ...] [--clock 14:00:00] [--out dir]
```

`--roi` 用 0~1 的相对坐标框出关心的区域（比如餐桌），只比这块，其他地方有人走动也不受影响。

## 按问题类型选方法

| 用户在问 | 方法 | 一般不需要 |
|---|---|---|
| **总览**：“今天发生了什么”“有没有事” | `day_digest.py` → 按性质分组讲；只有**未确认的急报/值守**才去看快照核实 | 翻所有图片 |
| **核实一条提醒**：“那个跌倒是真的吗” | 时间线里找到它 → 看快照（Read 图片）→ 看不清再从录像抽 3~5 帧 → 给出判断，并告诉用户怎么回复执事 | 全天扫描 |
| **东西变了**：“袋子什么时候放的”“谁动了 X” | 见下方“由粗到细找变化” | 逐张看图 |
| **作息/活动**：“妈起床了吗”“今天活动多吗” | 读 `activity_person_*.json`：`morning_first`、`hourly_active`、区域停留 | 任何图片 |
| **某个时刻**：“下午 3 点家里怎样” | 找最近的快照或进出记录；没有就直说当时没有画面留存，并提示去米家 App 回放 | 拿相邻图片去推测 |
| **现在**：“现在家里怎么样” | `python main.py cmd 状态`，再 `python main.py cmd 看看`（立即抓拍）后看图 | 读历史记录 |
| **系统问题**：“为什么没报”“为什么老误报” | `status.json` 的画面在线状态、`level_share`；时间线里的 `system` 行（断流、模式切换、镜头偏移）；同一位置反复出现的同类提醒 | 看图 |

### 由粗到细找变化

东西只会在**有人或宠物在场时**被动过，所以不用扫一整天，先把时间缩到“有人在的那几段”：

1. **粗：缩小时间。** 从时间线的进出记录和事件，以及活动统计里有活动的小时，列出候选时段。
2. **中：确认变了什么。** 用候选时段前后的空房间画面（`base_` 底图，或进出快照中没人的那张）做 `compare`，加 `--roi` 只看目标区域。只信 `changed: true`；`lighting: true` 表示是光照或镜头切换，不算。
3. **细：定位时刻。** 有录像（事件短录像，或用户从 SD 卡导出的文件）时，先 `scan --step 600` 找出变化发生在哪个 10 分钟区间，再在该区间 `bisect`，比较次数约为 log2(秒数)。
4. **讲出能确定到什么程度。** 没有录像就只能给范围，比如“10:29 的快照里还没有，15:44 的快照里已经有了”，不要编一个精确时刻。

二分的前提是变化**发生后一直保持**。东西放下又拿走、目标区域一直有人挡着，二分都会给错答案。这时改用 `scan` 缩小步长逐段看，并把这个限制告诉用户。各算法的细节和坑见 `references/methods.md`。

## 判断真假时要知道的

- 这套系统误报的主要来源是**静物被当成人**：雕像、挂着的衣服、夜间红外噪点、日出日落时的光线变化。同一位置、同一类型、反复出现，又一直没人回复的提醒，大概率是误报。看图确认后要明确说出来。
- `未确认` 不等于发生过，`主人确认误报` 就是误报。不要把未经确认的急报当成事实讲给用户。
- 画面中断（`stream_down`）、镜头偏移（`view_shift`）、执事重启（`supervisor`）期间什么都看不到。这段时间“没有提醒”不代表“没事发生”，要说清楚。
- 摄像头只看得到一个画面。门口不在画面里时，“有人回来”的意思是“有人出现在画面里”。

## 回答格式

用中文，先给结论，再给依据：

```
今天没有真事：3 条急报都是同一个位置的静物误报（已看快照确认）；有 1 人 10:12 回来、10:40 离开。

| 时间 | 发生了什么 | 性质 | 依据 |
|---|---|---|---|
| 10:12–10:40 | 1 人在客厅、餐桌活动 | 正常 | 进出快照 snap_arrival_…jpg |
| 10:29 | “有人倒地”急报 ×3 | 误报：快照里是石膏像 | snap_lying_long_…jpg |
| 14:00–14:30 | 画面中断 | 这段时间无记录 | stream_down |

需要你做的：给误报那条回复“没事”，执事会学习这个位置。
```

最后一行只在确实需要用户动手时才写（回复执事、去米家 App 回放某个时刻、把静物挪走等）。

## 隐私

快照和录像拍的是家里和家人。看图在本机进行。**未经用户同意，不要把图片、录像或文字记录发给任何外部服务**，也不要贴进 Issue 或公开渠道。回答里引用文件名即可，不需要复述画面中和问题无关的细节。
